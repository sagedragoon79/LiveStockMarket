# Live-Stock Market — handoff (July 26, 2026)

Farthest Frontier mod (MelonLoader 0.7 + HarmonyLib, FF v1.1.x Mono). Author: SageDragoon.
Identity: display name **Live-Stock Market**; repo/namespace/DLL/MelonPreferences category `LiveStockMarket`.

## Goal
A wool production chain, built in steps. Step 1 is the only thing in scope right now.

## Step 1 (agreed, ready to build): Goats / Sheep mode toggle on the goat barn
- Target: vanilla `GoatBarn` and `GoatBarn_Tier2` (identifiers confirmed in the decompile). NOT a building clone — a mode toggle on the existing building.
- Deliverable: injected **Goats / Sheep** buttons in the barn's info window, mode persisted per barn, default Goats, no behavior change yet. First in-game test: toggle → save → reload.
- Mechanism = the author's own proven pattern (documented in
  `Knowledge/FF-Modding-Knowledge/mod-patterns/building-work-modes.md`):
  - position-keyed static mode store (copy `WardenOfTheWilds/Systems/GraveyardModeStore.cs`)
  - info-panel button injection (copy `WardenOfTheWilds/Patches/GraveyardModeButtonPatches.cs`; original technique in `Tended Wilds/TendedWilds.cs`)
  - persistence via Save/Load postfixes appending the mode to the building's ES2 stream (copy `WardenOfTheWilds/Patches/GraveyardSaveLoadPatches.cs`)
  - load-phase application (Manifest Delivery's `OnGameFinishedLoadingFinalize` pattern; see `WardenOfTheWilds/Patches/FishingShackLoadPatches.cs`)
- Scaffold model: `BoatKeys/` (csproj with game-DLL HintPaths, `KeepClarityIntegration.cs`, deploy-while-running watcher; build with `dotnet msbuild`, deploy blocks while FF runs → `until ! tasklist | grep -qi Farthest; do sleep 20; done; cp …`).

v0.2.4 (September 5, 2026, after midnight) — storage marker hardened. The user saw every click open one Large Shelter's window after an untick → save → reload; the reload log was clean (no exceptions, no ES2 errors), so it is not confirmed as a stream desync, but the review found a real hazard: `TradingPost` overrides Save/Load and calls base FIRST, so the v0.2.3 marker sat mid-stream in its data — symmetric while the mod is installed, but an uninstall would break the trading post's load. ## Step 3 status (September 5, 2026): shearing built and deployed (v0.3.0), awaiting in-game test

Decisions (user): goats convert in place (species = the barn's mode; a formal cloned sheep animal is a later, large project — a new building, animal class + prefab + ES2 type + save block, herd asset, livestock item, and patches on the trading-post purchase flow, barn lists, fodder-type check and herder state); milestone order stays 3 → 4 → 5; the flip-flop exploit is closed by growth-gated yield rather than by locking the switch.

Design: `milkingItemID` getter postfix → wool for Sheep barns (the chicken coop's eggs override is the precedent; every consumer reads the property). Numbers come from a per-barn clone of the goat `LivestockHerdSetupData` (same guid string, so `Herd.Save` → `GetScriptableObjectFromGuid` still resolves the vanilla asset), assigned to the building field (gates `OnDayPassed` → `UpdateMilking`) and to `Herd.herdSetupData` (the loop reads it), then `barn.herd = barn.herd` rebuilds the capacity bundle. Fleece growth is a per-barn sheep-days counter (saved in the barn payload, now `LSM2` = magic, mode, sheepDays; `LSM1` still loads): yield = `WoolPerSheep × sheepDays / GrowthDays`, recomputed daily in an `OnDayPassed` PREFIX (before vanilla queues animals), growth restarts the day after the season ends. Switch rules: mid-session animals lose the session and take the new cooldown; others clamped to the new cooldown; the private queue is cleared; producer registration (`AddOrRemoveBuildingFromManufacturerDict`) flips milk ↔ wool. Every goat barn gets a permanent wool `SingleItemRequest` (TakeOut) beside vanilla's milk one, assigned/unassigned with the barn's logistics workers; `CheckWorkAvailabilityForTransferringMilk` is prefixed so each request is driven by its own product's count (vanilla would size the milk request from the wool count in Sheep mode). Seven live sliders under "Shearing".

An earlier draft locked the yield on the season's first day; dropped because a barn switched mid-season or a full-year season never sees a "first day" and would shear nothing forever. Proportional daily growth has no such event.

First in-game result (v0.3.0, September 5, 2026): the product swap worked (wool in the barn's product line, 25 produced) but the barn ran on GOAT numbers — capacity 120, 60-day milking cadence through late summer and winter. Log showed both switches applied the clone (the clamp used its 300-day cooldown). Cause: `LivestockBuilding.SetLoadedHerd(herd)` does `herdToSet.herdSetupData = herdSetupData` (the building's FIELD) on every adoption path — tier upgrade `PostRelocate`, `Start` with an abandoned herd, load finalize — and the upgraded barn was a new instance whose field still held the goat asset (only the name was re-applied on that path). v0.3.1: `SetLoadedHerd` postfix + `SetBuildingDataRecordName` postfix both call `SheepShearing.ApplyMode(barn, false)`; the per-barn clone is no longer destroyed with the building (an abandoned herd can still reference it mid-upgrade). Known cosmetic: herders still show "Milking Goats" (the villager state is shared by all goat barns; a per-barn label needs a UI patch — step 4).

Verified on v0.3.1 (September 5, 2026): shearing works — the wool line reads /300, no harvesting in winter, the herd is shorn in the first part of spring (season start day 78).

**Step 3 is complete as of v0.3.1.** Open items carried forward: herders still read "Milking Goats" (per-barn label needs a UI patch — step 4 alongside the sheep visuals); the placement sliders and test hotkey to strip or default-off before a release build; relocation of a Sheep barn resets it to Goats (step 1 caveat); uninstall notes in the README. Not committed yet. Watch for: the barn window's product line switching milk ↔ wool, the herder actually shearing (villager state is still `MilkingGoats`), haulers taking wool out, and `restored mode=Sheep (... sheep-days N)` after a reload.

## Step 5 status (September 5, 2026, pulled ahead of step 4): garments built and deployed (v0.4.2), in-game test in progress

Decisions (user): trade goods AND upgraded wearables for all three clothing slots — Winter Boots (Cobbler) replaces Shoes, Winter Cloak (Tannery) replaces Hide Coat, Woolen Clothes (Weaver) replaces Linen Clothes; recipes = the vanilla item's leather/flax × 2 + 5 wool; price = replaced item + 25%; no tech gate (wool availability, merchants included, is the gate); warmth 125% via a live multiplier; same wear as the replaced item; villagers prefer garments when in stock and keep a vanilla item until it wears out; work units same as the vanilla recipe. Icons: 256×256 PNGs in `art/` (winter_boots, winter_cloak, woolen_clothes), embedded with mipmaps.

Mechanics confirmed in the decompile: villagers seek exactly three clothing items via `SingleItemRequest`s in `VillagerItemRequester` (L128058+), gated by `VillagerHealth.ShouldSeekShoes/LinenClothes/Coat` (inventory `GetItemCount` of the vanilla item; coat also needs exposure ≤ `clothesSeekingExposure` and `villagerManager.isClothesSeekingTemp`); warmth = `ExposureClothingBonus() = hideCoatExposureBonus × GetTotalPercentIntact(itemHideCoat) + linenClothesExposureBonus × GetTotalPercentIntact(itemLinenClothes)` (asset defaults 0.3 / 0.1) and `curShoeBonus = shoeBonusBase × GetTotalPercentIntact(itemShoes)`; `TooColdSeekShelter` uses `GetMissingItems(Villager.clothingItems)`. All of it is inventory queries → `Patches/GarmentPatches.cs` postfixes `ItemStorage.GetItemCount(Item)`, `GetItemCount(ItemID)` and `GetTotalPercentIntact(Item)` for villager permanent inventories only (registered from the `VillagerItemRequester` ctor, dropped in `Cleanup`). Recipes: `Systems/GarmentRecipes.cs` clones each producer's vanilla recipe (found by produced item name in `BuildingData.manufactureDefinitions`), scales inputs, adds a wool `SourceItemDefinition`, pre-sets `ItemDefinition._item` (resolution is by class name), fixed guids (`5a1c0f0e-4c6d-4e00-9e01-0000000001xx`); work orders match by guid against the building's own list, so no SaveManager registration is needed (Farther Fabricating, decompiled from `ModCopies/Farther Fabricating.dll`, does the same). `GlobalAssets.ClearStaticReferencesToAllowUnloading` drops the item table, building table and UI asset map on game unload — item registration (`Systems/ModItems.cs`) and recipe injection are now keyed on the asset INSTANCE and re-run per game (wool had been getting away with a one-time flag because Unity kept the asset in memory).

Risk to verify first: `ItemStorage.GetItemCount(Item)` / `GetTotalPercentIntact(Item)` are small; if Mono's JIT inlined them into callers, the postfixes won't fire there and a villager wearing a garment would keep seeking the vanilla item. Fallback plan: patch the consumers (`VillagerHealth.ExposureClothingBonus`, `CalculateShoeBonus`, `ShouldSeek*`, `ItemStorage.GetMissingItems`, the disease inventory factors, the UI alerts) instead. Cosmetic gap: the villager window's equipment icons show the vanilla icon for a worn garment (step 4).

v0.4.1 (September 5, 2026, overnight): in-game the three producers' slots read "Unfilled" and refilled briefly, and with only the garment recipe enabled the workers idled without stocking anything. Diagnosis from the decompile: `Building.Awake` → `InitializeManufacturing` → `SetupManufacturingDicts` (L333200) copies every recipe line into `sourceItemDefsWithManuDefs` / `producedItemDefsWithManuDefs` with the copy constructors, which drop the private `_item` cache; `SetupManufacturingSourceItemRequest` (L334735) then dereferences the copy's `item`, and `ItemDefinition.item` (L187530) resolves by class name (`MiscUtilities.CreateObjectByName<Item>` = `Type.GetType(itemName)`), so the wool copy resolved to null, `Building.Awake` threw, and `SetupManufacturingProducedItemRequests` plus the rest of Awake never ran: no wool stocking request, no haul-out request for any product of those buildings (vanilla included), idle workers, and Essential Provisions' idle rule moved them to the laborer pool. Unity's Player.log is disabled in this install (`AppData/LocalLow/Crate Entertainment/Farthest Frontier/` holds no log), which is why the MelonLoader log looked clean. Fix (`Patches/WoolItemPatches.cs`): a prefix on the `ItemDefinition.item` getter resolves mod items by name into `_item` for any definition copy. Also new: `GarmentRecipes.ApplyPrefs` raises `ManufacturingSourceMaterialsChangedEvent` per recipe line so producers re-copy the lines (`Building.OnManufacturingSourceMaterialsChanged`, L333080) when the wool or input sliders move; the stocking target is `CheckWorkAvailabilityForManufacturing` (L334294): clamp(ceil((workers − in-progress orders) × numSourceItemsNeeded × stockNeededMultiplier), 0, capacity) per copied line, enabled if any recipe sharing the item is enabled. Recipe selection is `GetNextAlternatingManufactureDef` (L334986): it skips disabled recipes, prefers one under its batch quota, and returns null (worker idles) when a candidate is blocked on output space while the settlement holds its inputs. Built and deployed as v0.4.1, not committed (the user was asleep).

v0.4.2 (September 5, 2026, morning): the user confirmed v0.4.1 (workers stock and craft) and reported "Storage Limit Reached" on all three garments in the Settlement Items window while production continued. `UIResourceProductionPopupWindow.UpdateDynamicData` (L285693) and the top-bar icon (L287198) show that alert when `ResourceManager.SettlementCanStoreItem` (L173220) finds the item's canStore work bucket empty, i.e. no storage building accepts it. Cause: `StorageBuilding.Save` / `Load` (L338292 / L338403) persist `userDefinedAllowableItems` as the list of ALLOWED items, and the v1 `'LSMS'` marker made the loader treat that list as authoritative, so a save from before v0.4.0 (or one written by v0.4.0 / v0.4.1, which still wrote v1) came back with the garments unticked in every storehouse. Fix (`Patches/WoolStoragePatches.cs`): marker v2 lists the mod item IDs known at save time (`int count` + `int[] ids`); on load, a mod item not in the list is newer than the save and is allowed by default, an item in the list keeps the player's setting; v1 is read as "wool only", so the garments get allowed once. Trading Center: still no marker (mid-stream hazard on uninstall), tick by hand on older saves. Committed as step 5 (v0.4.2, September 5, 2026) after the user confirmed stocking, crafting, storage placement and the cleared alert in-game.
